# reference 0004: Расписание через рабочее окно вместо cron

Статус: принято (заменяет cron из `0001`, `0002` и `0003`)

Дата: 2026-10-12

## Контекст

В `0001`, `0002` и `0003` расписание описано как cron-выражение рядом с репозиторием, веткой и story. README описывает иначе: у инженера несколько тасок, по одной на репозиторий, у каждой своё рабочее окно (например, 9:00-18:00) и число коммитов в день, а случайные моменты внутри окна сервис выбирает сам

Cron задаёт регулярные точки времени, а коммиты нужны в случайные моменты внутри окна. README признан более верным источником, чем ранние записи в `reference/`

## Решение

Таска хранит:
- `start_time` и `end_time`: границы окна в формате `HH:MM` (в первой версии записи назывались `window_start` и `window_end`, переименованы спекой 002)
- `days`: дни недели запуска, ISO-нумерация 1-7, по умолчанию 1-5 (добавлено спекой 002)
- `commits_per_day`: число коммитов в день
- `active`: признак активности, выключенная таска не планируется (добавлено спекой 002)

Cron нигде не хранится. Расписание, как и репозиторий с веткой, принадлежит таске

Планирование: на каждый день для таски выбирается `commits_per_day` случайных моментов внутри окна, и они записываются в `planned_commits` (таблица из `0003`). Воркер берёт ближайшую запись по `run_at` тем же запросом, что описан в `0003`. План лежит в БД, чтобы рестарт пода не терял уже выбранные времена

## Последствия

- API принимает `start_time`, `end_time`, `days`, `commits_per_day`, `active` (см. `specs/002-models-endpoints/plan.md`)
- Библиотека cron не нужна, воркеру хватает выборки ближайшего `run_at`
- В схеме из `0003` у `users` нет полей репозитория, ветки, story и расписания, они переезжают в таблицу тасок, а в `planned_commits` вместо `user_id` появляется `task_id`. Схема переписывается в спеке про хранилище

## Открытые вопросы

- Часовой пояс окна: пояс сервера (в контейнере обычно UTC) или отдельное поле таски
- Допустимо ли окно через полночь или достаточно `start_time < end_time` (пока валидация требует второго)
- Когда строится план на день и что делать с таской, созданной или поднятой после рестарта посреди окна (выбирать моменты только из оставшейся части)
- Нужны ли выходные и праздники
