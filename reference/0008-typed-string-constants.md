# reference 0008: Закрытые наборы строковых значений оформляем именованным типом

Статус: принято

Дата: 2026-10-16

## Контекст

Статусы записи `planned_commits` (`planned`, `done`, `failed`) сначала были голыми строковыми константами, а поле `Status` имело тип `string`. В проекте закрытые наборы значений уже оформлены именованными типами: `Clock` для времени суток и `Weekdays` для дней недели

## Решение

Закрытый набор строковых значений оформляется именованным типом на основе `string` и типизированными константами. Для статусов записи это `db.CommitStatus` с константами `StatusPlanned`, `StatusDone`, `StatusFailed`, поле `PlannedCommit.Status` имеет этот тип

## Последствия

- В базе значение лежит обычным `text`, схема не меняется. GORM и pgx работают с таким типом как со строкой, в том числе в условиях (`Where("status = ?", db.StatusPlanned)`) и в `Updates(map[string]any{...})`. Проверено на живой базе: запись `done` и `failed`, чтение через `Preload`
- Защита от опечаток слабая: строковый литерал тоже присваивается полю такого типа, компилятор ловит только подстановку переменной другого типа. Основная польза в том, что значения собраны в одну группу, у типа есть место для методов, а стиль совпадает с `Clock` и `Weekdays`
- Значение из внешнего ввода к типу нужно приводить явно и проверять. Сейчас статусы приходят только из кода ядра, внешнего ввода нет
- Правило относится к новым закрытым наборам. Одиночные строковые константы (например, текст причины просрочки) типа не получают
