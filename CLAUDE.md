# Правила проекта

Здесь только стиль работы без избыточности. Основная информация о проекте в `README.md`

## Процесс: работа по спекам

- Работа идёт в spec-формате: сначала спека, код пишется по ней
- `reference/` хранит принятые решения и заметки, на них ссылайся в плане
- `specs/` состоит из пронумерованных подпапок (`001-...`), в каждой лежит `spec.md`
- Когда я говорю «приступай», бери подпапку с последним номером
- На основе `spec.md` создай рядом `plan.md` и `tasks.md`, затем остановись. Я либо подтверждаю их, либо нет. Без подтверждения код не пишется. После подтверждения реализуй по `tasks.md`
- Если из моих записей в спеке что-то совсем не ясно, спроси в чате до создания `plan.md` и `tasks.md`. Я либо доработаю спеку, либо отвечу напрямую

## Стиль и работа с кодом

- Прагматика важнее ортодоксии. Не предлагай «правильный» рефактор ради правильности
- **Никакой преждевременной оптимизации и задела «на будущее».** Пиши под сегодняшнее требование и не закладывайся на гипотетический второй инстанс, второй воркер, очередь из N элементов или масштаб, которого нет. Принцип Gray: **«будут бить, будешь плакать»**. Механизм добавляем, когда проблема реально пришла. Каждый лишний слой добавляет код и ментальную нагрузку: Gray держит весь дифф в голове разом, чтобы понять, не уехал ли ты с курса. Если ловишь себя на «пригодится, когда…», не добавляй, скажи об этом словами и оставь как есть.

## Работа с базой и компонентами через WSL

- Postgres поднимается контейнером в Docker внутри WSL
- На Windows локально нет ни Postgres, ни Docker. Команды `docker`, `psql` и всё остальное, что касается базы и её окружения, выполняй через WSL, например `wsl -e docker ps`
